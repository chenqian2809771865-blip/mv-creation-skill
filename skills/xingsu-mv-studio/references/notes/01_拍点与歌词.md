# 拍点与歌词：完整细则（原第 2 节）

> 这是 xingsu-mv-studio 技能的分层资料，原样从技能主文件移来（2026-11-04）。文中「x 节」「硬规则 N」指主文件同名小节；原 3.1 节在 references/notes/02_慢歌剧情.md，4.3 节在 references/notes/03_写镜头代码.md，4.6 节在 references/notes/05_竖屏2x3.md。维护时在当前仓库中更新对应文件，由版本控制记录改动。


- **时间基准**：片段时间 = 原曲时间 − 起点。片段开头常有数字静音，从第一个非零样本切起。用户给的 mp4 可能画面全黑、只有音频，直接抽音轨当片段用。结尾若先有一段数字静音、之后又响起一小截，那是 DAW 循环录屏的接缝，切在静音处，通常正好落在小节首拍（《第三人称》）。
- **拍点**：`scripts/beat_track.py` 出拍表（小节首拍、每拍的鼓和贝斯能量），用它找全停、断鼓、只剩军鼓的空档，作为定格、抛物、换场的位置（references/beat-sync.md）。
  - 速度恒定的录音室或 DJ 版：把高置信拍点拟合成恒定网格（中位残差一般 2–4 ms）；平均 conf 低多半只是鼓稀。速度会漂的歌才逐拍插值。说唱等底鼓稀的段落 beat_track 可能多插一拍（《100》）：高置信拍分前后两段各拟合周期，周期相同、外推正好差整数拍，就把前段索引平移后合拟一条网格（原拍表另存 `beats.tracked.json`）。小节首拍不在 k % 4 == 0 上时整体平移拍号，B[0] 可以是负的（《99》说唱 116 BPM，+1）。
  - 用户给的片段是二次剪辑时，恒定网格的残差呈锯齿（慢慢漂几十毫秒再突跳），突跳处就是拼接点：按突跳点分段，各段对底鼓起音单独拟合（《去北极忘记你》3 段）；beat_track 的平滑跟踪会把跳变抹成偏差。两种速度拼接的片段（《东京不太热》前 8 小节是升半音加速版 128.02、副歌起原速 120.85，比值 1.059）套单一网格残差上百毫秒，拍表里连续一串 conf 0 就是切换处：两段各拟合，拼接点取两条网格差得最小的那一拍。
  - 现场乐队录音（无 click）整首对恒定网格漂 0.3–0.4 秒：不硬拟合，镜头按段落和歌句切（分镜用秒写，`L(i)` = 第 i 句首字、`K(k)` = 拍点，只用来定段落落点；《我好想你》）。用户说「不用节拍网格」时也这样做。
  - 长前奏（《我好想你》38 秒）先用分频能量 + 频谱图拆段（钢琴 / 全乐队 / 急停余音），每段配一种开场手法；乐队急停那一下可以做“关灯”。
  - 慢歌的 DJ 版常被测成倍速（八分音符底鼓）：《你瞒我瞒》测出 152 BPM，体感是 76（底鼓在体感 1、3 拍，军鼓在 2、4 拍）。这时体感拍取偶数 k、一小节 8 个 k；`common.py` 里 `G.BEATS = B[0::2]`（角色律动跟体感走），`bump` 只推体感拍；小节相位按断鼓结束、副歌进来的那一拍定，不照搬 `downbeat_phase`；逐拍帧条也只看体感拍。
- **歌词**：`scripts/align_lyrics.py` 出逐字时间（人声分离 + SenseVoice + 对齐）。
  - ASR 和用户文本不一致的地方列给用户（告知，不等回复），按实际演唱改；同音误识别保留用户文本。
  - 识别为空，说明是纯器乐版，转用 references/music-lyrics.md 的纯器乐流程。
  - DJ / 混音版识别率常只有四五成：用户素材视频自带的字幕可以交叉核对句首。用户歌词里没有的人声切片（含前奏人声）不加字幕，列给用户（《第三人称》《苦咖啡·唯一》）。
  - 两层人声同时唱（采样的原曲 + 说唱，《苦咖啡·唯一》4 秒）不硬排成先后两句：主行照常，上方加一行小字卡拉 OK（该包 render.py 的参数版 `karaoke(t, LY_SUB, y=930, size=44, …, backing=True)`，半透明深色底条），SRT 里两条 cue 重叠照出。英文按词给时间，文本照用户原文的空格（「Demo word示例文本…」不补空格）。附唱拟声（示例拟声甲、示例拟声乙）会被 ASR 听成别的词，align 还会把它们塞进相邻句的空隙甚至人声静音段：按短窗 ASR、音高跳变和人声能量复核，卡拉 OK 里附唱小一号、换色（《东京不太热》）。
  - 同一旋律的两句（常相隔整 8 小节）有一句识别差时，比对两句人声的音高曲线，吻合就把识别好的那句逐字时间平移过去（《我的名字》：一句只认出 6/13 字，平移 32 拍后音高逐点吻合）。
  - 识别率很低（退出码 4）时，先核对歌词和音频是不是同一首、同一版本。片段配整首歌词会误报，先看报告里片段内逐句的识别数和起止是否合理（references/music-lyrics.md），LRC 整体偏移看 drift 表。副歌逐字重复时全局对齐会把整段挤错位：只给片段内的句子（`clip_lyrics.txt`）重跑（《超级棒棒糖》25.8% → 84.5%）。
  - 认不出、漏掉的字（含片段末尾重唱第 1 句被判 not found）：短窗 ASR（5 s 窗、每 2.5 s 一窗，《超级棒棒糖》包 `assets/engines/watercolor-modules/超级棒棒糖/asr_win.py`）时间戳 −0.08 秒、吸附到人声起音手填；没唱到的字时间放到片尾之后。末句长音会被截短，按人声能量手改；英文词（baby）被拆成字母单位，两两填同一时间。
  - 用户说“从 [00:39.90] 某句开始”而这句在 LRC 里出现好几次时，按 ASR 听到的下一句定实际起点，开工消息里告知。
  - 报告里“靠能量补出来的句首”要复核，尤其是上一句尾音拖进断鼓段、下一句是很轻的弱起时（《你瞒我瞒》被补晚了 2 秒）：对那一段单独跑 SenseVoice（粤语歌用 `language='yue'`）看 token 时间，再按人声起音和音高（粤语声调高低）逐字定；脚本原始结果另存 `lyrics.auto.json`。
- **LRC 必须重新校准**：LRC 常来自别的版本，偏差会越积越大（《后来》从 +0.8 秒累积到 +12 秒；加速版比 LRC 快 6–11%）。
