# 拆参考视频与节奏诊断

有参考片，或用户觉得成片"碎""拖""平"时阅读。可以按用户要求提炼并应用参考片的像素密度、配色、光照、构图、角色比例、动画、剪辑和字幕规律。人物、道具与剧情按用户选择设计；不要把某款参考的具体内容自动当作新项目设定。

多款参考先分别建立证据，再按 [多参考综合规范](references/multi-reference.md) 确定主参考、可组合的特点和项目制作规范。下面负责单款参考的拆解与核对，分析结果必须回到该项目的规范和样片验收中。

## 拆参考片

1. **规格与有效画面**：用 ffprobe 记录实际分辨率、帧率、时长和可读到的编码参数。手机录屏可用 `cropdetect` 辅助找黑边，再检查多个时间点，手动确认有效画面。记录裁边范围、画幅和不确定项；抖音界面、账号文字、播放器字幕及压缩伪影不算作品的美术规则。不要套用其他参考片的尺寸或裁边值。
2. **对齐到对应音乐**：先核实每款视频与其音乐、歌词的对应关系。用多个分散位置的独特乐句、瞬态和人声事件核对位置；重复乐句会使整段互相关误配，相关峰只能作为候选。只有确认音频连续且未变速时，才采用固定偏移，并写明正负方向，例如 `原曲时间 = 视频时间 + offset`。恒定变速时用多个锚点估计 `原曲时间 = a × 视频时间 + b`，并核对片头、中段和片尾；变速曲线、删节、重排、重复或混音需要分段映射，各段单独记录视频区间、原曲区间、映射关系与核对依据。无法确认的区间明确标为待核对。
3. **抽帧看**：每 0.25 秒抽一帧，拼成带视频时间标注的联系表，作为全片总览。人物动作、循环周期、视差、镜头运动和转场需再查看连续视频，或在关键区间加密抽帧到能够分辨实际变化，必要时逐帧检查；不能凭稀疏静帧推测完整动作。切点可用帧差粗找（变化像素占比 > 0.45 仅作候选阈值，需按素材调整），叠化、划变、闪光和镜头运动均需人工核对。
4. **逐镜头与逐乐句记录**：记录视频时间区间、对应音乐时间区间、画面内容、景别、颜色、文字、人物动作、背景运动、运镜、切点和转场；再注明与已核对的鼓点、人声、歌词或段落变化的关系。人声起点以实际音频为准，字幕仅作线索；分清音乐事件驱动与恰好同时发生。每项附时间码与抽帧或试听依据，并区分观察事实、推测和建议。
5. **像素风参考**：在有效画面的多个平坦区域和主体边缘估计像素格与缩放方式，行程长度可作辅助；下载、重采样和压缩可能改变测量结果，不能直接认定为源工程网格。排除 UI、边框和压缩噪声后，可用 kmeans 取 4–8 个主色，描述主导色彩关系；这些聚类中心不是整片总色数或硬性限色要求。FFT 中的格纹信号也可能来自录屏与缩放，需要结合画面核对。将像素格、调色板、动画帧保持时长等参数标明为估计值，并写出证据与可信程度。
6. **公平对比**：分别保留原始输出和比较用版本。按本次参考的有效画幅、显示大小与可确认的压缩条件制作预览，缩放像素画时先明确使用的插值方式；不硬编码旧项目的尺寸或码率。参考与新歌不同时，按相似的音乐功能和镜头任务（如主歌人声、重拍切换、情绪高潮）选取代表性片段，对比数量按片长与验证任务决定，比较静帧、连续动作、歌词可读性和音乐同步；不能只挑相同秒数或依赖压缩掩盖差异。

## 镜头长度分布

这是诊断工具，不是目标值。镜头长度没有统一标准，但分布能说明"碎"或"拖"的感受从哪里来。统计时间轴里每个镜头的长度：

```python
import statistics
cuts = [0, 2.4, 3.1, 6.8, ...]   # 各镜头起点（秒），最后加上片尾时间
lens = [b - a for a, b in zip(cuts, cuts[1:])]
print('中位 %.2fs' % statistics.median(lens),
      '短于1.5s %.0f%%' % (100 * sum(l < 1.5 for l in lens) / len(lens)),
      '长于4s %.0f%%' % (100 * sum(l > 4 for l in lens) / len(lens)))
```

- 一个参考数据：曾有一版成片中位约 1.25 秒、64% 的镜头短于 1.5 秒，观众反馈像幻灯片、跟不上故事。
- 反过来，镜头普遍很长、主体又小，容易显得平淡。
- 拿自己的分布和参考片的分布比较，比单看感觉更容易定位问题；是否调整仍按歌曲和故事决定。
