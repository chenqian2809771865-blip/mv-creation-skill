# 环境实测（随平台变化，用前以当次实测为准）

> 仅适用于 Claude 桌面版 / 云端会话；其他环境直接写本地文件。以下涉及 device_*、get_device_info、SendUserFile、stagedPath、xfer.sh 的传输与设备说明仅在该环境生效。


每条都标了最后验证时间，与当次实测不符时以实测为准，并顺手更新这里。

| 项 | 实测 | 验证于 |
|---|---|---|
| 云端规格 | 2 核、约 8GB 内存，无 GPU | 2026-10 |
| 后台任务时长 | 后台任务约 2 小时会被杀。`mvrun.py` 默认每轮预算 6600 秒，到点前不再开新段，重复运行可续做 | 2026-10 |
| 同时编码的内存 | 两个 4K preset slow 编码器同时跑会 OOM（表现为 BrokenPipe）。锁 ref=4 后两路 4K 同跑约占 4GB，《后来》没出问题。宁可 2K、4K 各开一个进程、各带一个编码器，最后再混音轨 | 2026-10 |
| p5 模板（无 GPU） | 1920×1080 约 44–180 秒/帧，不可行。软件 GL 下单帧读回约 19 秒，绘制本身只要约 0.2 秒；用 `--stills` 测，不要拿 `--sheet` 小图估速度 | 2026-10 |
| Skia 水彩引擎 | 960×540 约 0.1–0.3 秒/帧（首帧含缓存约 2.7 秒），2K 约 0.3–1.3 秒/帧，4K 约 1.4 秒/帧，加 slow 编码约 3 秒/帧/进程 | 2026-10-29 |
| 像素引擎 | 320×180 约 0.01–0.03 秒/帧；640×360 约 0.1–0.4 秒/帧；×8 管道给 libx264 约 20 fps | 2026-10-29 |
| 测拍 / 歌词对齐 | `beat_track.py` 3 分钟歌约 6 秒、峰值约 0.6 GB；`align_lyrics.py` 约 1.5 分钟处理 1 分钟音频（分离约 52 秒 + 识别约 40 秒）、峰值约 3.6 GB，别和 4K 编码同时跑 | 2026-10-29 |
| 网络 | PyPI、npm、GitHub（含 releases 和 raw.githubusercontent.com）可用；`github.com/.../raw/...` 经代理可能返回 403；Hugging Face 不一定可用 | 2026-10-29 |
| 写回用户电脑 | 单个 MP4 约 25MB 以上会被拒（HTTP 400）；stagedPath 会重新封装 MP4/PNG；线路慢时报 wall-clock timeout | 2026-10 |
| 用户电脑上的 shell | `device_bash` 跑在用户机器上的 Linux 虚拟机里，看得到已连接的文件夹；默认不能删除，要先申请删除权限 | 2026-10-29 |

## 进程判断

判断“渲染是否还在跑”时用 `mvrun.py WORKDIR --status`，它读 `progress.json` 里记录的 pid。不要用 `pgrep -f`：它会把命令文本里含同样字样的等待脚本也算进去，结果队列永远不启动。
