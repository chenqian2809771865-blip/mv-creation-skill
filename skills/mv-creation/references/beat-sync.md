# 拍点与卡点

## 测拍

```bash
python3 scripts/beat_track.py song.wav --out data/beats.json [--from S --to S] [--click check.wav]
```

- **方法**：沿用用户工程里验证过的 `beats_refine.py`。先从 HPSS 打击层估出 BPM 和相位，然后从鼓最强的一段开始，向前、向后逐拍跟踪：每拍在 ±35 ms 内取峰，再按强度加权做 9 拍滑动线性拟合。速度会漂的歌也能跟住（原版只套一条恒定网格，漂移超过 35 ms 就丢拍；合成测试里原版只有 45% 的拍落在 20 ms 内，现在是 100%）。小节首拍由和弦变化（chroma 新颖度）加 0.5 倍底鼓能量判定。断鼓段的拍按两侧插值，标 conf 0，鼓回来后重新锁定。拍点落在起音上（比包络峰早 10 ms，可用 `--onset-delay 0` 关掉）。3 分钟的歌约 6 秒跑完，只依赖 numpy、scipy 和 ffmpeg。
- **输出**：
  - 每拍的底鼓、军鼓、贝斯、镲能量。
  - 逐拍表，列出拍号、小节.拍、时间、各能量和新颖度。用它找副歌前的全停、只剩军鼓的空档和断鼓段。
- **听一遍再用**：先用 `--click` 听一遍（每拍一声，小节首拍更高更响），确认找到的是正常速度，不是半速或倍速。只在第 3 拍打军鼓的半速感编曲默认会取慢速，需要时用 `--bpm-hint` 指定。抒情歌动作可以按半速设计。
- **已知局限**：完全没有鼓的段落结果不可靠；速度在断鼓段里突变时，断鼓段内的拍误差可达约 60 ms；全曲只选一个小节相位，中途插或删了小节的歌要用 `--from/--to` 分段测。
- **只要粗估时**：`beat_grid.py` 只给一个恒定 BPM 和相位，不能当逐拍结果用。
- **速度会漂的歌**：现场感的歌速度会漂，要用实测拍表，不套固定 BPM 网格。
- **自由速度段**：自由速度的前奏要按实测音点逐个对齐，比如《下雨了》的 `intro_onsets`。
- **没有鼓组的编曲**：看 150Hz 以下能量的抽空与回来，再用每 4 小节一次的镲作段落锚点（《晴天》管弦乐版）。

## 工程里怎么用

- **拍表插值**：拍表存进工程，按拍表插值（`beat_at(t)` / `time_of(b)`，见 `beat_track.py` 的文档字符串），不要套恒定 BPM。
- **拍号与秒分开**：时间助手不要把拍号和秒混用。例如 `es(t, 128, 128.8)` 里的 128.8 会被当成秒，小数拍号要先用 `kt(128.8)` 换算成秒。
- **镜头按拍号写**：分镜里的镜头按拍号 k 写，例如 `bar n = k0 + 4(n−1)`，再由拍表换算成秒（见水彩引擎的《失眠》范例）。

## 卡点规则（仅在用户要求“卡点”时启用）

- **事件落点**：切镜和大字落地放在小节首拍；每拍一个可见事件，比如落地、弹出、换帽、亮灯、翘板到底。
- **动作提前起**：动作要提前开始，让“到达”落在拍上；弹出类提前约 1 帧开始。
- **按帧末时刻采样**：事件出现在包含拍点的那一帧，画面误差 0 帧。
- **卡拉 OK**：逐字变色、弹字、换姿比音节提前 2 帧（0.083 秒），看起来更踩点。说唱可能在重拍前就开口，所以字幕时间以实际人声为准，不预设统一提前量。
- **相邻两句**：间隔小于 0.35 秒时，在下一句首字处直接换行，不交叉淡化。
- **镜头轻推**：每拍轻推一下，首拍 2%、其余拍 1.1%，0.09 秒回落，字幕不动。断鼓段幅度减半。
- **自检**：逐帧拆条并标出拍点所在帧，看事件是否正好落在那一帧。工具是水彩引擎随附的 `code/beatstrip.py`：每拍取前一帧、含拍点的帧、后一帧三帧对照。
