# 音乐与字幕

## 时间基准

- **先定区间**：先看音频时长和用户要求的区间。
- **片段时间**：截取从 `song_start` 开始的片段时，`片段时间 = 原曲时间 − song_start`。歌词、角色动作和切点都用同一个基准。
- **数字静音**：用户给的片段开头常有一段数字静音，从第一个非零样本 S0 切起。工程里记下 S0，所有时间按切过之后的片段计算。
- **结尾**：结尾淡出还是留白，由音乐决定。
- **有参考片时**：各款参考保留各自的视频时间和对应的音乐时间，映射方法见 references/reference-video.md。参考片的字幕起点、拍点、镜头秒数都不能直接搬到新歌上。

## 歌词逐字对齐

```bash
python3 -m pip install sherpa-onnx pypinyin      # 首次
python3 scripts/align_lyrics.py song.wav lyrics.lrc --out data/lyrics.json [--from S --to S] [--trim-s0]
```

- **输入**：用户的 LRC 或纯文本（一行一句）作为文本来源。脚本只给文本定时间，从不改写文本。没有准确歌词时先向用户索取，或标记待核对，不凭记忆补写。作词、作曲这类署名行会自动跳过。
- **流程**：用户工程里验证过的做法（`sep.py`、`align.py`、`asr_multi.py`、`prep_audio.py`）。
  1. 用 UVR `UVR-MDX-NET-Voc_FT.onnx` 分离人声，输出 `<out>.vocals.wav` 和 `<out>.inst.wav`。同一区间再跑时，可用 `--vocals` 复用人声，省掉这一步。复用时个别字可能和整条重跑差 0.1–0.2 秒（人声读回后的数值差会影响少数字的识别），整体准确度相同。
  2. 用 SenseVoice 在 10 秒和 13 秒两种重叠窗口里识别，每 2 秒开一个新窗口（可用 `--windows 8,10,12 --step 1.5` 改成 `align.py` 的设置）。
  3. 先做全局对齐，确定每个窗口对应哪一段歌词，这样副歌重复时也不会对错位置（旧 `align.py` 遇到逐字重复的副歌会错开 24 秒或漏句）。再在这段范围里做局部对齐。同拼音和常见的唱腔混淆（z/zh、n/l、-n/-ng 等）都算近似匹配，可用 `--eq 偷不,掉到` 补充本歌常见的误识别对。
  4. 每个字取各窗口时间里最集中的一组的中位数，再吸附到人声起音上（ASR 的时间戳比实际起音晚约 0.08 秒）。句首没识别出来时，用人声能量找起音。
  5. 句尾取人声比该句峰值低 22 dB 的位置，再加 0.15 秒。
- **输出**：
  - `[[开始, 结束, 文本, [逐字时间]], ...]`。逐字时间对应文本里每个非空格字符，和水彩引擎《失眠》范例的卡拉 OK 一致。要连空格也给时间（旧 `align.py` 的格式）时，加 `--space-times`。
  - `<out>.report.md`，列出：
    - ASR 与用户文本不一致的句子
    - 靠能量补出来的句首
    - 低置信的句子
    - 没找到的句子（例如 `--to` 之外的部分）
    - LRC 漂移表
- **报告怎么处理**：不一致处列给用户，按实际演唱修改；同音误识别保留用户文本。
- **退出码**：0 成功，1 出错（有明确提示），3 纯器乐，4 低匹配。
- **低匹配（退出码 4）**：识别出的字不到 35%（正常演唱一般能识别 60–90%）。JSON 照常写出，但报告顶部会有警告，因为很可能是歌词和音频不是同一首、同一版本，或者区间给错了。实测把《下雨了》（薛之谦）的歌词配上《那天下雨了》（周杰伦）时只有 6.3%。遇到这种情况先核对，不要直接用这份时间。
- **纯器乐版**：识别出的字不到 5%，就输出 INSTRUMENTAL、不写 JSON、退出码 3，这时转用下面的纯器乐流程。
- **模型**：首次运行时从 GitHub 下载（共约 230 MB），缓存在 `~/.cache/mv-creation/models`。
- **实测准确度**：《白兰花》前 98 秒对照当时校准的时间，24 句全部找到；句首中位差 0.065 秒、最大 0.175 秒，98% 的字差在 0.2 秒内。逐字时间整体早约 0.07 秒，正好是 ASR 时间戳的滞后量，那次校准很可能没做这项修正。
- **耗时**：在云端约 1.5 分钟处理 1 分钟音频，复用人声时约 40 秒。内存峰值约 3.6 GB，所以别和 4K 编码同时跑。

LRC 常来自别的版本，偏差会越往后越大：《后来》从 +0.8 秒累积到 +12 秒，《最甜情歌》的人声比 LRC 快约 11%。所以不能假定 LRC 的误差在某个范围内，一律按实际人声重新对齐。

## 纯器乐版

- **判断**：人声分离后识别为空，就是纯器乐。这时 LRC 是原唱的时间，不能直接用。
- **定段落**：把推测的段落表发给用户，确认两三个关键点。
- **找句首**：用 `pip install --no-deps basic-pitch` 找每句的起点（另装 librosa、pretty_midi、mir_eval、resampy，用包内的 `nmp.onnx`），按“音符数 ≈ 字数、句尾是长音”来判断。
- **画面呈现**：
  - 不做卡拉 OK，把歌词写成画面里的字：黑板粉笔、纸条铅笔、雾玻璃上的手指字。
  - 旋律唱到哪句就出哪句，每个字最多约 0.27 秒。
  - 实现见 `assets/engines/pixel-320-couple/code/lyr.py`（《晴天》）。水彩版的撕边纸条、按旋律逐词写出，见 `assets/engines/watercolor-modules/Rolling小苹果串烧/render.py` 和 `assets/engines/watercolor-modules/Rolling小苹果串烧/make_lyrics.py`。
- **字幕**：另外导出一份 SRT 备用。

## 数据与导出

```json
[[0.25, 2.8, "字幕示例"], [3.0, 5.2, "第二句", [3.0, 3.4, 3.9]]]
```

- **格式**：开始、结束都是片段内秒数，按开始时间排序。第四项可选，可以是逐字时间、歌手标记或选项对象；只用于工程内部，导出字幕时忽略。
- **导出命令**：

```bash
python3 scripts/lyrics_to_subtitles.py lyrics.json --out out/lyrics.srt      # .vtt 同理，覆盖已有文件加 --overwrite
```

- **JS 文件**：脚本也接受只含 `const LY = [...]` 的 JS 文件，只解析数据，不执行代码。

## 字幕排版

- **踩点**：逐字变色、弹字比音节提前 2 帧（0.083 秒），看起来更踩点。说唱可能在重拍前就开口，所以字幕时间以实际人声为准，不预设统一提前量。
- **相邻两句**：间隔小于 0.35 秒时，在下一句首字处直接换行。
- **像素卡拉 OK**：细节见 references/styles.md。
- **避让**：字号、位置、底板以在目标设备上能读清为准，并避开关键表演。

## p5 模板卡拉 OK

需要逐字着色时，在 `studio.html` 中加载 `src/karaoke.js`，放在 `timeline.js` 之后、页面初始化之前，然后填写 `LY`：

```js
const LY = [[0.25, 2.8, '字幕示例', { sing: 2.1 }]];
```

- **选项**：`sing` 是本句着色用时；`hold` 让上一句缩小并保留到下一句出现。
- **精度**：默认按匀速估计逐字着色，要精确同步就把真实的字级时间传进去。
- **位置**：模板歌词在底部约 `y=975–1070`，由 `window.overlayHook` 画在纸纹上方。
- **检查**：检查中文字体覆盖、长句溢出和多行衔接。
